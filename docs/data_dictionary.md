# OMOP data dictionary

Generated by `scripts/omop_build_report.py` from `src/cdm/omop.py` (the column definitions) and `results/research/a_omop/build.json` (the null rates). Do not edit by hand; a test checks this file matches. Null rates are from no build yet: null rates fill in from the first pipeline update.

These tables are a **portfolio build on public research images** (HAM10000 and ISIC Archive collections), not a clinical data source. They live in the Databricks workspace as `workspace.cdm.omop_<table>`, built by the Lakeflow pipeline from `silver_metadata`, so Unity Catalog lineage runs bronze → silver → OMOP.

## Conventions and assumptions

- **Standard:** OMOP CDM v5.4 column names, order and types. `image_occurrence` follows the OHDSI medical imaging extension proposal (Park et al., JAMIA 32(10):1533, 2025, doi:10.1093/jamia/ocaf091). Extension columns are marked as such.
- **Dates are placeholders.** The sources record no dates. Every date is 2000-01-01, and `year_of_birth` is 2000 minus the approximate age (5-year bins). Use them for age only, never for time.
- **Person** is a real patient only where ISIC records a patient ID (MSK collection 289, Buenos Aires, PAD-UFES-20). Elsewhere one person is one lesion, which over-counts people. `person_source_value` says which rule applied.
- **Condition** is one per lesion: ISIC `diagnosis_3`, else the 7-class label. When a lesion's images disagree, the most common value wins, then a specific diagnosis over a NOS one. `condition_status_source_value` keeps how the diagnosis was made.
- **IDs** are 60-bit hashes of source keys, stable across rebuilds. The DICOM UIDs are surrogates (`2.25.` + a UUID5 of the image ID), because there is no DICOM.
- **Concepts:** `config/omop_concepts.csv` maps each source value to an OMOP concept looked up in an Athena download (`results/research/a_omop/concept_check.json`). Concept 0 means no verified concept. SNOMED codes and names are not in the repository (SNOMED license); `omop_concept` holds them inside the workspace only.

## FAIR, honestly

- **Findable:** table and column comments in Unity Catalog, and this dictionary.
- **Accessible:** inside the Databricks workspace only. There is no public endpoint.
- **Interoperable:** OMOP CDM v5.4 tables and OMOP standard concepts.
- **Reusable:** license and attribution per image in `omop_image_occurrence`. CC-BY-NC images are non-commercial only.
